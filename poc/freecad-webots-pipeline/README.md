# FreeCAD → Webots Pipeline POC (issue #24)

Standalone spike validating **only the pipeline mechanics** — FreeCAD STL→STEP
import/export, URDF authoring, and Webots URDF import/wheel-joint
articulation — using a public, already-rigged wheeled robot (TurtleBot3
Burger, ROBOTIS, Apache-2.0). Deliberately decoupled from this workspace's
own pendulum/wheel/servo geometry in `inverted-pendulum-project/03_Parts/Generators/`
(not touched by anything here).

See the full write-up in [`findings/FINDINGS.md`](findings/FINDINGS.md) and
the asset attribution record in [`NOTICE`](NOTICE).

Relates to #9 (this project's own URDF export design) and #10 (this
project's own Webots import) — this POC exists to de-risk those before real
project geometry has to carry that risk.

## Layout

```
poc/freecad-webots-pipeline/
  00_fetch_turtlebot3_assets.sh   Stage 0 — fetch pinned-SHA TurtleBot3 assets
  reference/                      gitignored — fetched by the script above
  freecad/
    01_import_and_export_step.py  Stage 1 — Mesh -> Part.Shape -> STEP (headless FreeCAD)
    01_import_and_export_step.sh  FREECAD_BIN wrapper for the above
    02_roundtrip_check.py         Stage 1b — re-import STEP, diff vs source, re-export mesh
    output/                       gitignored — generated per run
  urdf/
    turtlebot3_poc.urdf           Stage 2 — hand-authored POC URDF
    meshes/                       gitignored — copied from freecad/output/ (see Stage 2 below)
  webots/
    worlds/turtlebot3_poc.wbt     Stage 3 — generated by urdf2webots (gitignored)
    protos/                       Stage 3 — generated PROTO (gitignored)
    controllers/wheel_articulation_check/wheel_articulation_check.py
    run_batch.sh                  runs the generated world in --batch --mode=fast
  findings/
    FINDINGS.md                   Stage 4 write-up (feeds #9 Stage 4 and #10)
```

## Why assets aren't committed

Per the issue #24 plan, TurtleBot3 assets are fetched on demand and
gitignored rather than committed: acquisition is pinned to an exact commit
SHA (see below), so a fetch is fully reproducible, and this avoids growing
the repo with vendored STL/mesh binaries (this repo's `.git` is already
sensitive to STL bloat — see #9's notes on `03_Parts/Generators/`).

The generated Stage 1 STEP files, Stage 1b round-tripped mesh re-exports,
and Stage 3 Webots PROTO/world are likewise gitignored (`freecad/output/`,
`urdf/meshes/`, `webots/protos/`, `webots/worlds/*.wbt`) — all reproducible
by re-running the stages below.

`urdf/turtlebot3_poc.urdf` itself **is committed** — it's small, hand
text-authored, and is the one artifact of this POC meant to be read/reviewed
directly (its `<mesh>` filenames point at `urdf/meshes/`, which you
regenerate locally — see Stage 2).

## Reproducing end to end

Requires: headless FreeCAD 1.1.3 (`FREECAD_BIN`, e.g.
`~/.local/opt/freecad-1.1.3/usr/bin/freecadcmd`), Webots R2025a
(`/usr/local/bin/webots`), and the `pendulum-tools` mamba env with
`urdf2webots` installed (`mamba run -n pendulum-tools pip install urdf2webots`).

### Stage 0 — fetch assets

```bash
cd poc/freecad-webots-pipeline
./00_fetch_turtlebot3_assets.sh
```

Fetches `turtlebot3_burger.urdf` + `burger_base.stl` + `left_tire.stl` +
`right_tire.stl` from `ROBOTIS-GIT/turtlebot3` at the pinned SHA recorded in
the script (re-resolved once via `git ls-remote` at implementation time —
see the script header for how to deliberately re-pin), verifies the LICENSE
at that SHA is Apache-2.0, and writes/refreshes `NOTICE`.

### Stage 1 — FreeCAD import & STEP export

```bash
export FREECAD_BIN=~/.local/opt/freecad-1.1.3/usr/bin/freecadcmd
./freecad/01_import_and_export_step.sh
```

Imports each of `burger_base.stl`, `left_tire.stl`, `right_tire.stl` as a
`Mesh.Mesh`, converts to a `Part.Shape` (per-facet `makePolygon`/`Face` →
`makeShell`/`makeSolid`, same pattern as
`inverted-pendulum-project/03_Parts/Generators/01_convert_servo_stl_to_step_via_freecad.py`),
and exports STEP files into `freecad/output/`. Writes
`freecad/output/stage1_conversion_report.json`.

**Performance note:** `burger_base.stl` has ~96.5k facets — see FINDINGS.md
for concrete timing at this facet count with the naive per-facet conversion
pattern (it is meaningfully slower than the ~35.7k-facet servo mesh this
pattern was originally built around; treat this as a real data point for
#9's own mesh sizes, not something this POC pre-optimizes around).

### Stage 1b — STEP round-trip check

```bash
"$FREECAD_BIN" -c "__file__=r'$(pwd)/freecad/02_roundtrip_check.py'; exec(open(__file__).read())"
```

Re-imports each STEP file, diffs bbox/volume/facet-count against the source
mesh, writes `freecad/output/roundtrip_report.json`, and re-exports each
round-tripped shape as an STL (`freecad/output/<link>_roundtrip.stl`).

Then copy the round-tripped re-exports where the POC URDF expects them:

```bash
mkdir -p urdf/meshes
cp freecad/output/burger_base_roundtrip.stl urdf/meshes/
cp freecad/output/left_tire_roundtrip.stl urdf/meshes/
cp freecad/output/right_tire_roundtrip.stl urdf/meshes/
```

(Per decision #4 in the approved plan, `urdf/turtlebot3_poc.urdf` references
these FreeCAD round-tripped re-exports, not the pristine vendored STLs in
`reference/meshes/` — this exercises FreeCAD's own mesh-export path, which
is the actual point of the spike.)

### Stage 2 — POC URDF

`urdf/turtlebot3_poc.urdf` is already hand-authored and committed — a
structural copy of the fetched reference URDF (`base_footprint` → fixed
`base_joint` → `base_link`; `wheel_left_joint`/`wheel_right_joint` as
`type="continuous"`, `axis="0 0 1"`, `origin rpy="-1.57 0 0"`; fixed
`caster_back_joint` with a box-collision-only `caster_back_link`, no
mesh — matching the real ROBOTIS URDF). Nothing to run for this stage
beyond the mesh copy above.

This URDF is **not** produced by, and does not feed into, issue #9's future
`urdf_builder.py` / `10_export_urdf.py` exporter — it's hand-maintained for
this POC only.

### Stage 3 — Webots import & articulation test

Baseline sanity check (independent of this POC, confirms the local Webots
install/EXTERNPROTO resolution works at all):

```bash
webots --batch --mode=fast --stdout --minimize \
  /usr/local/webots/projects/robots/robotis/turtlebot/worlds/turtlebot3_burger.wbt
```

Convert the POC URDF to a Webots PROTO:

```bash
mamba run -n pendulum-tools python3 -m urdf2webots.importer \
  --input=urdf/turtlebot3_poc.urdf \
  --output=webots/protos/TurtlebotPoc.proto \
  --target=R2025a
```

Then build/run the world (see FINDINGS.md for exactly what this step
produced/required in practice) and run the articulation check:

```bash
./webots/run_batch.sh webots/worlds/turtlebot3_poc.wbt
```

`webots/controllers/wheel_articulation_check/wheel_articulation_check.py`
commands both wheel motors to a fixed velocity, steps the simulation a
handful of times, and reports pass/fail based on whether the wheel joint
position sensors actually moved.

### Stage 4 — Findings

See [`findings/FINDINGS.md`](findings/FINDINGS.md) for the full write-up:
unit-conversion behavior, the `rpy="-1.57 0 0"` wheel-axis gotcha, STEP
round-trip fidelity/performance numbers, Webots URDF-import behavior, and
`urdf2webots` quirks — written for whoever builds #9 Stage 4 and #10.

## Stop-rule note

Per decision #6 in the approved plan: if Stage 3 Webots URDF import failed
3 times with genuinely distinct fixes attempted, the plan was to stop there
and document the failure itself as the Stage 4 finding rather than keep
iterating. See FINDINGS.md for whether that happened on this run.
